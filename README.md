# vpn-client

VPN-клиент для Windows с раздельной маршрутизацией:

| Трафик | Куда |
|---|---|
| Корпоративный: домены из настроек, подсети и DNS-домены от сервера OpenVPN | OpenVPN |
| Зарубежный | VLESS (Reality / TLS) |
| Российские сайты, локальная сеть, всё остальное | напрямую |

Сетевую часть выполняет [sing-box](https://sing-box.sagernet.org/) 1.14+: TUN-интерфейс,
встроенный OpenVPN-клиент, VLESS и DNS. `vpnclient` собирает для него конфиг из
простого профиля и `.ovpn`, запускает и корректно останавливает. Отдельный
OpenVPN ставить не нужно.

```
profile.yaml + corp.ovpn ──► vpnclient ──► конфиг sing-box (через stdin) ──► sing-box
                                                                     ├─ TUN (весь трафик ПК)
                                                                     ├─ openvpn-client → корпоративная сеть
                                                                     ├─ vless → зарубежные сайты
                                                                     └─ direct → остальное
```

## Установка

1. Скачайте `vpnclient-vX.Y.Z-windows-amd64.exe` со страницы
   [Releases](https://github.com/maks-ard/vpn-client/releases/latest) и запустите.
2. Подтвердите запрос Windows на права администратора — **один раз**: программа
   поставит себя в `C:\Program Files\vpn-client`, зарегистрирует службу «vpn-client»
   и добавит ярлык в меню «Пуск». Скачанный файл после этого можно удалить.
3. **Настройки** → вставьте ссылку на подписку (`https://…`) или `vless://…` →
   **Выбрать** файл `.ovpn` от администратора.
4. **Главная** → большая кнопка. Иконка в трее: серая — отключено, жёлтая — подключение,
   зелёная — подключено, красная — ошибка.

Если подписка и OpenVPN ещё не добавлены, кнопка подключения открывает настройки.
Файл OpenVPN можно выбрать через обзор или загрузить, введя путь строкой.
При открытии настроек без OpenVPN клиент автоматически ищет профили в
`%USERPROFILE%\OpenVPN\config`, `%ProgramFiles%\OpenVPN\config` и `config-auto`
(также в Program Files (x86)), включая непосредственные подпапки и каталоги,
заданные в реестре OpenVPN GUI. Выберите найденный профиль для импорта:
автоматически конфигурация не заменяется. Поиск не читает содержимое файлов,
не сканирует весь диск и не требует прав администратора. Хранилище OpenVPN
Connect не разбирается. Стандартные пути описаны в
[документации OpenVPN GUI](https://github.com/OpenVPN/openvpn-gui#adding-an-openvpn-configuration-file).
После импорта поле пути скрывается; заменить профиль можно кнопкой «Заменить».
Пояснения к настройкам доступны по значку `i` при наведении или фокусе клавиатуры.
Корпоративные домены по умолчанию не заданы: добавьте нужные в настройках.
Уже сохранённый список доменов при обновлении не меняется.

Дальше всё работает само:

Настройки редактируются как черновик и сохраняются кнопкой **«Применить»**:
добавление нескольких доменов вызывает одно переподключение. До сохранения
можно отменить изменения, после сохранения доступен возврат предыдущих настроек
в рамках текущего запуска окна. Импорт и удаление OpenVPN выполняются отдельно.

В списке VLESS показываются понятные названия стран и локальные SVG-иконки.
Страна определяется только по явным признакам в названии подписки, без внешней
геолокации. Неизвестные или неоднозначные узлы называются «Сервер N»; исходное
имя доступно при наведении. Технический идентификатор переключения не меняется.

На главной доступны результаты HTTP-проверок четырёх сервисов с временем
проверки и кнопкой **«Проверить сейчас»**. Они не подтверждают доступность
аккаунта. После пробуждения Windows проверки обновляются без пересоздания TUN.
В настройках подписки отдельной строкой показывается срок действия из
`Subscription-Userinfo` провайдера. Истёкший срок выделяется красным, окончание
в ближайшие три дня жёлтым. Точное время доступно при наведении, в местном часовом
поясе. Если провайдер не передал дату, клиент не считает подписку бессрочной.
Диагностика в настройках сначала показывается для просмотра, затем копируется
отдельной кнопкой. В неё не включаются журнал, адреса, домены, пароли и подписки.

Автоматическое восстановление после смены сети и VM-проверка чистой установки
пока не завершены. Сценарии установки описаны в `docs/installation-checks.md`.

- **служба** держит VPN (окно работает без прав администратора, поэтому в нём
  работают PrtSc и программы для скриншотов) и стартует вместе с Windows;
- закрытие окна не отключает VPN. Явный «Выход» из трея сначала отключает VPN,
  затем завершает интерфейс. Также можно отключиться большой кнопкой или пунктом
  «Отключить» в трее;
- **обновления** служба проверяет раз в 6 часов (и по кнопке «Проверить обновления»
  в настройках), скачивает новую версию с проверкой SHA-256, ставит её и
  перезапускается; окно перезапускается следом. Пока VPN включён, новая версия
  скачивается и проверяется в фоне, без разрыва соединения. Готовое обновление
  устанавливается автоматически после пяти секунд непрерывного простоя VPN,
  повторно нажимать «Проверить обновления» не нужно. До перезапуска службы
  новое подключение блокируется. При ошибке установки автоматические повторы
  прекращаются, ошибка показывается в настройках; повтор запускается кнопкой
  проверки. Очередь готового обновления хранится в памяти службы: после её
  перезапуска версия проверяется и загружается заново;
- после неожиданного завершения sing-box приложение повторяет подключение
  до трёх раз с паузой 5 секунд. Отказы авторизации OpenVPN выводятся отдельно,
  без бесконечных повторов. Раз в минуту отдельно проверяется HTTP-доступ через
  текущий прокси к YouTube, Instagram, ChatGPT и Claude. Неудачные проверки
  показываются в предупреждениях; это не проверка входа в аккаунт или всех функций
  сервиса. Автовыбор самого быстрого сервера по-прежнему использует YouTube.

Настройки, журнал и распакованный sing-box лежат в `%ProgramData%\vpn-client`
(доступ только у системы и администраторов). Удалить службу:
`"C:\Program Files\vpn-client\vpnclient.exe" --uninstall` от имени администратора.

## Антивирус ругается на файл

Некоторые антивирусы (например, Касперский: `UDS:Trojan.Win64.SilentCryptoMiner`)
по репутации и поведению принимают программу за майнер: новый неподписанный exe
ставит службу SYSTEM, распаковывает внутри себя `sing-box.exe` и сам обновляется.
Это ложное срабатывание — код открыт, exe собирается GitHub Actions, контрольная
сумма лежит рядом в `.sha256`. Если антивирус удалил файл, служба не запустится:

1. восстановите файлы из карантина;
2. добавьте в исключения `C:\Program Files\vpn-client\` и `C:\ProgramData\vpn-client\`;
3. запустите скачанный exe ещё раз;
4. отправьте файл как ложное срабатывание (для Касперского — https://opentip.kaspersky.com).

## Сборка из исходников

Нужен Go 1.26+. GUI собирается только под Windows (кросс-компиляция с Linux работает, CGO не нужен):

```bash
GOOS=windows go build -ldflags "-H windowsgui" -o vpnclient.exe ./cmd/vpnclient
```

Такая сборка не содержит sing-box: для разработки задайте путь к нему в `VPNCLIENT_SINGBOX`.
Релизная сборка (с встроенным sing-box, иконкой и манифестом) делается в
`.github/workflows/release.yml` по тегу `vX.Y.Z`.

Для отладки без GUI есть консольная утилита `cmd/vpnctl` (`check`, `config`, `run`)
с профилем в YAML, см. `profiles/example.yaml`.

## Как разводится трафик

1. Домены из `corporate.domains` с поддоменами, подсети из `corporate.subnets`,
   а также маршруты и DNS-домены, которые прислал сервер OpenVPN, идут через OpenVPN.
   Корпоративные домены резолвятся DNS-серверами из OpenVPN.
2. Частные сети (LAN) и программы из `routing.direct_processes` идут напрямую.
3. Домены из `routing.proxy_domains` идут через VLESS, домены из `routing.direct_domains` напрямую.
4. Домены `.ru`, `.su`, `.рф`, списки `geosite-category-ru` и `geoip-ru` идут напрямую
   (это можно отключить через `routing.russia_direct: false`).
5. Всё остальное идёт через VLESS, его DNS ходит через DoH по VLESS.

`redirect-gateway` и `block-outside-dns` от сервера OpenVPN игнорируются, поэтому
весь трафик через корпоративную сеть не уходит. IPv6 по умолчанию блокируется,
чтобы не было утечек мимо TUN.

## Ограничения `.ovpn`

Поддерживается `dev tun` с сертификатами и ключами в PEM (inline или файлами), с
`tls-auth`, `tls-crypt` и `tls-crypt-v2`, а также с логином и паролем. Не
поддерживаются PKCS#12, сертификаты из хранилища Windows, блоки `<connection>`,
`dev tap` и подключение через HTTP/SOCKS-прокси. Неизвестные директивы выводятся
как предупреждения.
